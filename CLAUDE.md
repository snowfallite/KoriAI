# CLAUDE.md

Ядро проекта подключается в каждую сессию автоматически:

@tech.md

`tech.md` является единственным источником истины. Подчиняйся ему дословно. Контракты не выдумывай: нужного контракта нет в ядре, значит выдай `CONTRACT GAP` (§19.2) и остановись. Запрос пользователя противоречит ядру: назови противоречие и спроси, ядро молча не меняй. С пользователем общайся по-русски.

## Старт сессии

1. Определи режим и задачу по первой строке запроса: `Режим: feature F-07`, `Режим: contract`, `Режим: owner S1-05`. Режим не назван: `feature` и ID задачи из запроса. ID задачи нет: спроси.
2. Первый ответ начни строкой `Режим: <mode> · Задача: <id> · CORE_VERSION: <n>`.
3. Режим `feature`: проверь `SKELETON_READY` в шапке `tech.md`. Значение `no`: задачу не начинай, перечисли незакрытые пункты чек-листа §22.1.
4. `git fetch` и `git rebase origin/main`, либо новая ветка `<issue-id>-<slug>` от свежего `main`. `CORE_VERSION` в ветке не ниже, чем в `main`.
5. Прочитай карточку задачи в §22, эталонный слайс (§16.3: `backend/app/domains/portfolio/`, `frontend/src/routes/(app)/portfolio/`) и разделы контрактов, на которые ссылается карточка.

## Жёсткие правила

- Одна сессия, один режим, одна задача. Сфокусированный diff вместо всего приложения сразу.
- Пиши только в зону режима (§4.2, §19.1). Зона задачи S2 перечислена в её карточке §22.2. Нужна правка вне зоны: `CONTRACT GAP` или просьба сменить режим.
- Раскладка слайса копирует эталон. Своя раскладка запрещена.
- Миграции руками не пишутся. Сгенерированные файлы (`frontend/src/lib/api/**`, `backend/migrations/**`) руками не правятся.
- Никаких торговых методов T-Invest и песочницы. Никаких секретов в коде, логах, контексте LLM.
- `.env` не читай. Нужен секрет или реальный вызов API: попроси пользователя выполнить команду.
- UI собирается только из `$lib/ui` и `$lib/components` (§13). Новый общий компонент или проп: `CONTRACT GAP` на §13.2.
- Числа в ответах агента берутся только из инструментов (AD-08, §9.10).
- Разработка и тесты идут на фейках (`*_MODE=fake`). Реальные API вызывает только `just smoke-external` по просьбе пользователя.
- Запрос на подтверждение правки файла общей или контрактной зоны (`.claude/settings.json`) в режиме `feature` означает, что ты вышел из зоны: остановись и объясни зачем.

## CONTRACT GAP

Формат блока и что считается разрывом: §19.2. Выдай блок, не пиши код с выдуманным типом и предложи два пути:
1. переключиться в режим `contract` сейчас (§19.3), потом вернуться к задаче;
2. отложить: дай готовые заголовок и тело задачи Linear с меткой `contract-change` и продолжи независимые части задачи.

Заглушка допустима только в ветке, с комментарием `CONTRACT-GAP(<task-id>)`. С такой меткой PR не пройдёт CI.

## Цикл задачи в режиме feature

1. Ветка `<issue-id>-<slug>`.
2. Тесты из критериев приёмки карточки, сначала красные (§14). Если установлен skill `engineering:testing-strategy`, загрузи его перед тестами. Обязательные типы: контрактные на стыках, идемпотентность каждой задачи очереди, путь ошибки через `FaultPlan`, property-based на чистой логике, агентные и e2e по карточке.
3. Реализация по эталону до зелёного. Маленький коммит после каждого осмысленного шага (§17), каждый коммит по возможности проходит тайпчек.
4. `just gate`.
5. Самопроверка по DoD и чек-листу ревью §18: каждый пункт с ответом «да» или «нет». Если установлен skill `engineering:code-review`, проведи ревью через него.
6. PR: заголовок `<ISSUE-ID> <type>(<scope>): <summary>`, тело по шаблону (§17). Метки не ставь: их ставит пользователь.
7. Итог пользователю: что сделано, ссылка на PR, что проверить руками.

## Режим contract

Шаги §19.3. `CORE_VERSION` растёт ровно на 1, строка Changelog в том же PR. Затем `just migration <slug>` (если менялась схема), `just gen`, фейки и адаптеры, контрактные тесты. Метка PR: `contract-change`.

## Режим owner

Задачи S1 и общая зона (§4.2). Контрактную зону по уже описанной версии ядра реализуй без правки `tech.md`, PR получает метку `core-impl`. Изменение решения §3.2: сначала ADR (§19.5); если установлен skill `engineering:architecture`, пиши ADR через него.

## Проза

Коммиты, PR, комментарии в коде: английский, формат §17. Тексты UI, промпты, описания инструментов: русский. Везде дисциплина stop-slop: активный залог и императив, конкретика, без em-dash и филлеров.

## Команды

`just dev`, `just gate`, `just test`, `just test-int`, `just test-fe`, `just e2e`, `just gen`, `just seed`, `just migration <slug>` (только `contract`). Полный список: §15.4.
